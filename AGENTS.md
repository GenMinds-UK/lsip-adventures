# LSIP Adventures

## Project overview

- LSIP Adventures is a TanStack Start + React + TypeScript app for 16–18 year olds in England: "A quest to explore how A level choices can lead to real opportunities." It covers the five North West Local Skills Improvement Plan (LSIP) areas first: Cheshire and Warrington, Cumbria, Greater Manchester, Lancashire and Liverpool City Region.
- The journey has ten stages: the `/` title screen, `/where` (town or city → LSIP area), `/subjects` (3–4 A levels), then `/journey/skills`, `/local`, `/national`, `/overlaps`, `/quests`, `/contacts` and `/summary` (with a PDF download).
- Every result is calculated from hardcoded research data: a subject × skill matrix scored against each area's LSIP skills demand. There are no AI calls and no data is collected from students.
- Use British English in all user-facing copy, in a plain, encouraging tone for teenagers. Frame demand positively and never tell a student a subject is a poor choice.
- Preserve the friendly retro arcade visual language in `src/styles.css` and the components under `src/components/arcade/`.

## Repository layout

- `src/routes/` holds the TanStack file-based routes. `src/routes/journey.tsx` is the layout for stages 4–10. Preserve `src/routes/__root.tsx` and its `<Outlet />`.
- `src/components/` holds reusable UI grouped by feature. Prefer extending an existing feature folder over adding a new top-level pattern.
- `src/lib/scoring.ts` holds the pure scoring maths. `src/lib/results.ts` turns it into what the screens show. `src/lib/journey.ts` has the stages, search-param parsing and `useJourney()`.
- `src/data/subjects.ts` is the curated A level list. Subject names are stable keys used across all research data.
- `src/data/generated/` is compiled from `research/data/` by `npm run data:compile`. Never edit it by hand.
- `src/data/regions/<id>.content.ts`, `src/data/synergies.ts` and `src/data/skills-content.ts` hold hand-written content, validated by `npm run data:check`.
- `research/` holds the methodology, source lists, evidence notes and the CSV source of truth (`research/data-schema.md` describes the format). `scripts/` holds the data scripts.
- `src/integrations/supabase/`, `drizzle/` and `supabase/` hold the database scaffolding left from the earlier AI version. It is currently unused.
- `src/routeTree.gen.ts` is generated by TanStack Router. Do not edit it by hand.

## Data rules

- Every number and fact shown to students must trace back to a cited source: the region evidence notes in `research/regions/`, `research/sources.md`, or the `source`/`evidence` columns in the CSVs. Mark anything unverified with `VERIFY:` rather than guessing.
- Change scores and facts in `research/data/*.csv`, then run `npm run data:compile`. After changing M, D or N, also run `npm run data:analyse` and then `npm run data:compile` again, so the tier cut-offs stay calibrated.
- Contacts are organisations only: never named individuals or personal email addresses. Link to official websites and record the date each link was checked.
- Do not add student data collection, analytics that identify students, or AI calls without an explicit requirement. If a database is used again, keep Supabase RLS locked down and keep `SUPABASE_SERVICE_ROLE_KEY` server-side.

## Working conventions

- Use the `@/*` alias for imports from `src/`, except in files that the Node data scripts load (`src/lib/scoring.ts`, `src/data/subjects.ts` and the content files). Those use only relative or type-only imports. Keep TypeScript strictness intact.
- Follow the existing Tailwind CSS v4 utilities and CSS variables. Keep layouts mobile-ready and accessible, including keyboard operation and reduced-motion support. Use `ArcadeDialog` (Radix) for modals so that focus is trapped and restored.
- Use the existing `lucide-react` icons and feature components where applicable, rather than introducing parallel UI primitives.
- Do not edit files marked as generated, including the Supabase generated clients and middleware, `src/data/generated/` and `src/routeTree.gen.ts`, unless regeneration is the intended change.
- Keep changes focused. Do not rewrite published Lovable history, force-push, rebase, amend or squash pushed commits.

## Local development and checks

Install dependencies with `npm i`, then run `npm run dev` for the Vite development server.

Before committing, run:

```sh
npm run lint
npm run typecheck
npm run build
npm run data:check
```

There is no test script. `npm run data:compile` doubles as the data validation step.
